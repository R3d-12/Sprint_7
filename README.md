# Sprint_7 — автотесты API Яндекс Самокат

Финальный проект 7 спринта: автоматизированное тестирование API учебного сервиса **Яндекс Самокат**.

- **Сервис:** https://qa-scooter.praktikum-services.ru/  
- **Документация API:** https://qa-scooter.praktikum-services.ru/docs/

---

## Что делает проект

Проект проверяет API сервиса: создание курьера, авторизацию, создание заказа и получение списка заказов. Тесты пишутся на **pytest**, запросы — через **requests**, отчёты — **Allure**.

### Покрытые ручки

| Ручка | Файл тестов | Что проверяется |
|-------|-------------|------------------|
| Создание курьера | `tests/test_courier.py` | Успешное создание, дубликат, отсутствие обязательных полей (login, password), коды ответа |
| Логин курьера | `tests/test_login.py` | Успешная авторизация, неверные логин/пароль, отсутствие полей, несуществующий пользователь, наличие `id` в ответе |
| Создание заказа | `tests/test_order.py` | Создание заказа с цветом BLACK, GREY, оба цвета, без цвета (параметризация), наличие `track` в ответе |
| Список заказов | `tests/test_orders_list.py` | Код 200 и то, что в теле ответа приходит список заказов |

### Вспомогательный код

- **`utils/helpers.py`** — базовый URL, генерация случайных строк, регистрация курьера, авторизация, создание заказа. Тестовые данные создаются в тестах через эти функции.

## Как развернуть и запустить у другого пользователя

Нужны: **Python 3** (желательно 3.8+), доступ в интернет (запросы к qa-scooter.praktikum-services.ru).

### 1. Клонировать репозиторий и перейти в папку проекта

```bash
git clone <url-репозитория> Sprint_7
cd Sprint_7
```

### 2. Создать виртуальное окружение и установить зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate   # macOS / Linux
# .venv\Scripts\activate    # Windows
pip install -r requirements.txt
```

### 3. Запустить тесты

```bash
pytest tests/ -v
```

С сохранением результатов для Allure:

```bash
pytest tests/ -v --alluredir=allure-results
```

### 4. Посмотреть Allure-отчёт

```bash
allure serve allure-results
```

Отчёт откроется в браузере. Папку `allure-report` (после `allure generate`) при желании можно пушить в репозиторий отдельно.

## Задание (кратко)

- Протестировать ручки API (в т.ч. вручную в Postman).
- **Создание курьера:** можно создать; нельзя создать двух одинаковых; обязательные поля; код ответа; успех — `{"ok":true}`; ошибки при отсутствии полей или при повторном логине.
- **Логин курьера:** успешная авторизация; обязательные поля; ошибка при неверном логине/пароле или отсутствии полей; при авторизации несуществующим пользователем — ошибка; успешный ответ содержит `id`.
- **Создание заказа:** можно указать цвет BLACK, GREY, оба или не указывать; в ответе есть `track`. Использовать параметризацию.
- **Список заказов:** в теле ответа — список заказов.
- Код тестов и Allure-отчёт — в репозитории. В тестах проверяются тело и код ответа, тесты независимы, тестовые данные создаются перед тестом и при необходимости удаляются после.
